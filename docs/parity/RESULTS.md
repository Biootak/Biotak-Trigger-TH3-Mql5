## 8. Session 2 (later the same day) — the compat layer

Scope of this pass: `MT5Compat/MQL5Compat.mqh` (1973 lines) read end to end against the
MQL4 contract it emulates — Phase 3 §A (series indexing / off-by-one), §C (calculation
lifecycle), §D (historical vs live), §E (numeric). It had never been audited; the earlier
session's cross-tree metrics do not cover it, because `module-report.py` compares the
`Biotak/` twins and does not diff the shim.

### 8.1 What was found and changed

Two defects in one function, `CompatRefreshChartData()` — the code that makes
`Time[]/Open[]/High[]/Low[]/Close[]/Bars` answer like MT4's predefined arrays. Every module
in the product reads them, so both are upstream of every number the indicator draws.

* **MT5-PAR-013 (critical)** — the re-sync chose "shift one slot right" from the bar *count*
  alone. A count that rose by one has two causes on MT5 (a bar opened at the newest end; a
  history download appended one bar at the oldest end) and the shift is right for only the
  first. On the second, all historical slots land one bar too new **and never heal**, because
  the state machine only re-syncs on the next count change.
* **MT5-PAR-014 (high)** — that shift lived inside the 500 ms throttle. When the throttle
  held on a *genuine* new bar, control fell into the foot block and wrote the live
  High/Low/Close into index 0 while the slot still carried the previous bar's Time/Open — one
  torn bar, exactly the frame an attach or a TF switch produces when it lands near a bar open.

Fix `P-MT5-SERIES-01` / `-01b` (`MT5Compat/MQL5Compat.mqh:939-1002`, `:1101-1126`): the shift
now requires the newest bar's **time** to have advanced, the throttle gates the full-history
copy only, and the live-value foot block writes only when the arrays are aligned with the
count the caller reported (`bars == g_seriesSyncedAt`). Three statements and one gate — the
subsystem was not rewritten, because the cause was established first (mandatory rule 6).

### 8.4 Independent review (Phase 6, step 9)

The fix was handed to a reviewer with no stake in it — read-only, asked to be adversarial and
to trace every path through `CompatRefreshChartData()` (first call, steady count, genuine new

`OnInit`/`OnTimer` callers that pass no live values). It found four things; all four were
handled, and each disposition is recorded rather than argued:

| Review finding | Disposition |
|---|---|
| The harness stamped the throttle inside its `_shift()`, which is precisely what `-01b` removed from the source — so the `AFTER` column was not the shipped code | **Confirmed and fixed.** The stamp is now modelled per variant (`BEFORE` stamped, `AFTER` never). Without it, a regression that re-added the stamp would have printed identical verdicts. | A residual torn index 0 when a new bar arrives with an **unchanged count** (a rolling series) | **Checked against the platform reference, then closed as not reachable**: the vendor documents `rates_total` as the series available to the indicator and states the chart-bar limit affects the *initial* count only. | The source comment (and this session's first draft) claimed an ordinary **TF switch** could hit the throttle window | **Rejected by evidence and corrected in place.** MT5 deinitialises the indicator on `REASON_CHARTCHANGE` — the tree's own `P-PERF-95` note (`Biotak/EventHandlers.mqh:1204-1216`) documents exactly that for a sibling static — so a fresh instance resets the throttle.
